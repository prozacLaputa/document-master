# 季度规划

用于季度工作、产品或技术规划；通用排版和首稿验收仍按基础规范执行。已有用户指定的结构优先，不扩展到晋升材料、PRD 或所有技术方案。

## 先让读者知道方向从哪里来

按“上季度做了什么 → 当前怎么看 → 目标怎么对齐 → 为什么优先做这些事”推进，再介绍工作方向。回顾区分已完成动作、可观察结果和遗留问题；不要把动作写成已证明的收益。

当前判断承接回顾中的问题或证据，目标对齐说明与上层目标的联系，优先级说明取舍理由。没有证据、目标口径或承诺时保留未知，不为结构完整编造数字和共识。篇首可有短摘要，但不能让摘要替代方向之前的推导；不把所有判断都提前展开成一大块。

## 工作方向：先总览，再解释关键判断

工作方向一章可先用一两句高亮块说明季度取舍，例如本季聚焦什么、暂不推进什么及条件。依据放到后面的段落。

总览按“要解决的问题 → 本季度怎么做 → 季度交付”对应；方向名称可放在问题列或按需要单列。单个动作使用同段加粗短标签，多个交付物使用格内原生自动编号，不把整段理由塞进总览。

重要方向在表下设小节，展开目标、判断、动作和交付边界。独立判断用加粗小标题，解释另段；并列理由拆无序列表。每个小节增加依据或必要细节，不逐行复述总览。

明确本季可承诺的产物与需要后续证据的结果。例如“形成候选场景和试点建议”不等于“扩大推荐”；后者须等试点结果。关键条件按通用语义强调：待核实或需优先排查的条件标黄，已明确的风险标红；一般交付边界可只加粗。颜色不得提高事实强度。

## 文末单独维护实时路线图

路线图按具体任务列出优先级、推进时间和进展，必要时保留方向字段便于定位。同一方向的任务若时间或状态不同就分行，不把方向名当成唯一任务。已知时间与状态按来源写，未知项不自行承诺；静态文档表由授权更新维护，不宣称自动同步。

方向总览说明季度打算交什么；路线图说明任务何时推进、当前到哪一步。两者职责不同，更新任一处都核对交付口径是否冲突。需要筛选、计算或多人填报时按 [维护型表格](maintained-tables.md) 判断是否换用更适合的载体，不擅自迁移。
