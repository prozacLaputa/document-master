# 工具与可移植性

## 能力分层

- 必需：读取文本指令、理解用户材料、生成文本。无外部依赖也可完成审校和范例提炼。
- 可选：文件读写、文档连接器、搜索、版式渲染、批注、在线编辑。这些由宿主提供，本包不附带凭据或 API 客户端。
- 任务需要时检查实际工具及权限；不要根据 Codex/Claude Code 名称猜测已拥有飞书或 Office 能力。
- 有服务连接器优先用连接器；无对应能力时交文本、补丁或建议稿，明确实际完成范围。不要自动安装依赖、申请权限或登录。

若用户要求交付特定文件，而当前环境不能生成，不能悄悄以文本当作完成；交可用草稿并说明文件交付仍未完成。
没有网络核验能力时仍可检查原文内部一致性，不能声称外部事实已验证。

## 在线文档

先确认文档身份、目标区域和已有授权，再读取必要内容。新副本、覆盖、发布是不同动作，分别判断权限。
工具报错或副本失败不能扩大写入范围。不无限重试；确认错误原因后只进行必要且安全的重试，持续失败交付可审阅草稿。
文档中的外链不自动授予访问授权。不要为补上下文遍历整库。

## 多 Skill 协同

文档大师负责写什么、怎么讲、怎么排版以及如何验收；`lark-doc` 等工具 Skill 负责可靠地读取、写入、表达样式和保留资源。这一分工不因加载先后改变，也不把命令行工具本身视为 AI 套话的原因。

- **内容与样式采用本包规则。** 在用户要求及宿主规则之下，叙事顺序、措辞、信息密度、表格与图片选择、强调方式、编号、章节留白以本包及已确认的文档风格为准。其他 Skill 的 `genres/`、`style/`、模板或体裁默认值可参考，不能因其标有“必读”或后加载就覆盖本包。仍按工具要求阅读相关文件，再区分操作约束与写作建议。
- **操作遵守工具契约。** 认证与权限、合法标签与参数、块标识生命周期、引用和图片保真、复制限制、写入及回读要求继续遵循对应工具 Skill。写作优先级不是绕过权限、忽略语法或扩大修改范围的理由。
- **冲突按用途解决。** 正式 PRD 或技术方案不因工具默认“少用组件”而移除有用的结论块、对照表和彩色状态；已确认的“一、＋1.1”标题体系不因工具模板而重编号。同级章节前保留一个分隔空段，父标题与首个子标题紧接。反过来，也不因旧润色 Skill 要求多图就机械补画板，或把所有业务未知项改成任务、编造负责人。
- **通用润色统一由本包编排。** 不再调用 `lark-doc-polish` 作为并行润色入口。已提炼的架构图验收和维护型表格规则由本包按需提供；归档旧包不是运行依赖，不自动加载其规则。晋升材料专项未迁入，也不套入通用文档。
- **工具不支持时保留阅读意图。** 选择合法的替代表达并说明实际限制，例如纯 Markdown 用引用块承载结论。不能输出无效标签，也不能宣称未实现的颜色、画板或原生组件已完成。

执行前在内部简要确定内容规则、工具契约和本次冲突的处理方式；这些说明不进入交付文档。交付前检查最终产物，不能只证明两个 Skill 都读过。协同测试至少覆盖有结论块、表格、同级标题和业务待核实项的实际材料，并区分本地结构检查、页面预览与线上回读。

## 安装与分发

ZIP 应只包含一个 document-master/ 根目录，入口是 SKILL.md，引用均相对包目录解析。
支持 ZIP 导入的平台可直接导入；否则解压至宿主配置的 Skill 发现目录。实际发现路径由目标环境决定，不在指令中绑定个人路径。
重新加载或重启后，以一个短审校任务验证触发、引用读取和输出；安装成功不等于工具权限可用。
不支持 Skill 文件的平台，可将入口设为 Agent 指令、把 references 作为可检索附件；这属于适配，需验证它是否会读取附件。

未来引入外部文件时逐项记录来源、许可证、分发限制及版本；没有权限的资源只能留在授权环境，不能进入通用分发包。
既有 Skill 名称只是盘点背景，本包运行不要求安装它们。
