# 已确认偏好与适用范围

来源：本包创建会话中用户明确提出的要求。此文件是随包携带的配置，不是自动读取个人历史的授权。

- 目标：更好地管理 AI 文档产物，语义通畅、少错误、少 AI 味。
- 尊重原作者意图，保留必要信息与论证，不为文采过度改写。
- 默认减少铺垫、重复解释和空泛小结，优先高信息密度；精简不能丢失关键条件，也不强制所有文体采用短列表。
- 依据用途与读者选择结构，不同文档类型不能一刀切。
- 参考文档的段落长度、标题层级、留白、图文布局与强调方式属于可跨文体迁移的基础能力，不只在相同题材下使用。0.5.0 根据明确反馈加入；具体色值、字数和组件数量不机械照抄。
- 对信息多、不能再压缩的说明与论证长文，默认先用高亮块直白说结论，再用分论点及依据支撑；关键短语适度加粗，红绿等颜色按明确的概念、推荐或状态语义使用。此规则于 0.4.0 根据明确反馈加入，不套用个人叙事或改变只改字、只排版的任务范围。
- 0.6.0 起默认主动使用表格做对照、用画板讲清关系与分支，适当使用彩色重点和高亮块；不因题材不同而跳过，也不机械堆组件。父标题紧接首个子标题，不额外留空行；所有同级章节之间留一行，包括大标题和小标题，不限文体。具体规则见 [基础排版](layout-basics.md)。
- 0.6.2 起明确：技术方案的结论先行是分析判断先行，不是助手工作进度先行；命令、分支和详细调查过程通常放附录，关键证据结果与限制留在判断附近。
- 问题指出具体位置和理由，区分文字问题、事实疑点与用户决策。
- 主动建议并推进授权范围内的下一步，避免每一步都等用户催促。
- 一个入口，以 ZIP 分发，可供 Codex 或 Claude Code 类 Agent 加载。
- 可以借鉴授权好文档；提炼适用写法，不挪用其中的业务事实。
- 覆盖原稿、重要删除、结论改变和对外发布遵守入口的确认边界。

尚未确认：个人署名、固定字体配色、统一篇幅、默认存储目录、永久自动复核范围、各文体的特定声音。不要自行补成偏好。
不要把历史身份、年龄、关注点写进正文或配置。

修改这份配置：
1. 单次反馈先应用于当前文档。
2. 若可能成为长期偏好，提出一条具体规则及适用场景，附当前例子。
3. 用户明确确认长期生效后才更新；记录范围和版本。
4. 不修改宿主记忆、其他 Skill 或全局配置，除非这些对象也获得单独授权。
