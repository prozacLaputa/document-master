# 交付前质量门槛

先自行验收，发现问题就在授权范围内修订并重新检查，不把第一稿直接当成完成。检查对象是交付物，不是规则是否被提及。通常完成一轮，仍发现实质问题则继续；重复修订已无改善或受工具限制时，明确剩余缺口，不声称全部达标。

1. **原意与证据**：回查数字、范围、条件、否定、异议和待定事项；建议不能变决定。只排版时正文逐字保留，新增摘要也属于内容改动。
2. **读者能否先抓重点**：需要结论先行的材料，首屏给核心判断和影响判断的限制；技术方案若首屏只写完成了哪些工作、运行了哪些检查，则不通过，需改为方案可行性或选择判断；正文提供不同的依据，不能只换词重复。
3. **废话与自我解说**：删除“下表清晰展示”“这张图的重点是”等只解释排版的句子，直接说业务信息。图例、必要读图说明和证据条件保留。开头、正文、结尾不可反复重述同一结论。表格行若只重复列标题就删去；已在表中列出的投入数字，正文只有新增推理时才重复。待定事项不在开头和结尾整组照抄，结尾仅补新的待决策点。
4. **组件是否有用**：对应信息主动用表格，关系与分支考虑画板；每个组件回答明确问题。无独立信息增量的图表删去或合并，不把多用表格理解为所有文字表格化。
5. **页面是否好读**：父子标题紧接与同级章节分隔是两项独立检查，不能用“全文无空段”代替通过。逐一检查所有大标题与小标题边界（包括表格、图片、普通段落结束后的标题），以及父标题到首个子标题；再检查表头、列宽、重点标注和图中文字。Markdown标题之间用于解析的一个空行不等于富文本空段，不为紧凑破坏语法。
6. **实际完成范围**：写入后回读，能渲染则查看首屏、密集区域、图表和结尾。窄屏宽表需横向查看时明确说明；不得把源码检查或桌面抽样写成全平台验收通过。

修正只覆盖已获授权的修改。改变原结论、删除重要信息、覆盖原稿等仍遵守确认边界；不要为了过质量门槛越权。交付仅简述关键修改及尚未解决的问题，不把内部检查表灌进正文。

## 最终交付物复核

交付前按最终文档做一次逐项复核，并把结果留在交付记录中。

- 逐段检查编辑过程说明，表格、图注和附录也在检查范围内。分清可删除的助手工作旁白和必须保留的业务未知项。
- 逐例核对场景、图片、图注及链接，查看实际图片，检查图注是否因图片替换而过期。图片未获取或仅看到占位时如实报告。
- 检查全部表头、标签列和普通列表的样式，再检查大标题、小标题和图片后的留白。
- 写入后回读最终内容，对照来源检查数字、状态、边界、链接和图片。同步到另一文档时在目标文档重做检查，不能沿用审阅稿的验收结果。
- 有页面工具时查看首屏、密集区域、图片和结尾。结构校验与视觉抽查分别记录，不能把它们写成全平台保证。

富文本材料可运行 `python3 scripts/check_document_consistency.py final-document.json` 辅助定位混杂表头、圈号和常见编辑旁白。该工具只输出需要人工复核的位置，不修改文档。它不能判断图文是否对应、事实是否正确或颜色差异是否有意，零发现仍须完成上面的语义复核。

自动表头检查只支持 `thead/tr/th` 的背景属性与 `b` 加粗标记，文字提示扫描 `p/li`。标签列、对齐、列宽及其他格式由人工补查。引用反例、实验记录或必要的证据限制也可能触发提示，不能把发现列表当作删除清单。

## 标题间距的执行检查

批量清理空段或重排标题后，从最终成稿重新检查。富文本 XML 或飞书完整 fetch JSON 可运行：

```sh
python3 scripts/check_heading_spacing.py final-document.json --require-sibling-blank-line
```

在 Skill 根目录运行；此参数仅用于已选择“同级章节前一个空段”的排版方式。使用可调原生段距时不加该参数。工具只读，报告具体标题和问题，不自动删改、不联网；输入不能是 Markdown。若使用节选，需要包含前一小节及父标题，缺少上下文不能据此证明全文通过。

检查失败先修成稿，再回读重跑。结构通过仍需查看实际页面中一组父子标题、至少一处大标题边界和一处同级小节边界（优先包含表格或图片的边界）；不能把脚本通过写成视觉通过。没有 Python 或 XML 时按同样两项检查手工复核，并准确报告范围。
