# 知识讲解与技术分享

适用：帮助读者建立概念、理解原理或辨析方法的教程、入门分享、知识说明。
不替代技术方案评审、操作手册、汇报或个人文章。先识别读者已有知识与本次学习目标，能从材料推断就不重复问。

## 学习路线
围绕读者会遇到的问题推进：熟悉场景 → 新概念 → 运作过程 → 限制与应用，是可选路线而非固定章节。
全景型分享适合从生活场景或业务演进切入，再展示问题与技术关系。
专题型长文先用简短结论块说清核心认识，再逐层讲概念、机制、比较和边界；必要时补阅读路线。不要用目录替代核心认识。结论块与强调方式遵循 [编辑规范](editorial-rules.md)。
短说明不必加路线图；不知道的前提明确写出，不能虚构受众背景。
类比仅解释有对应关系的部分，说明类比在哪些地方失效，不把类比当证明。

## 根据阅读问题选择版式

| 阅读问题 | 可选形式 | 使用条件 |
|---|---|---|
| 各部分是什么关系 | 关系图 + 就近的解释 | 图承担关系，正文补条件，不逐字重复 |
| 两个概念容易混淆 | 对称分栏 | 统一比较维度、粒度和顺序；内容太长改上下排列 |
| 一件事如何发生 | 一个具体例子 + 流程 | 事件、状态、方向明确；异常分支不能被美化掉 |
| 多种方案如何取舍 | 比较表 | 候选真实，维度有用，优缺点有依据，缺证据不填猜测 |
| 方法为何有必要 | 失败场景 → 原因 → 应对 | 真实案例有来源，构造案例明确标记 |
| 哪个条件最容易漏 | 短提示块或图注 | 一块只强调一个重点，不靠颜色单独传递含义 |

按基础排版主动选择有用的图表，不要求全部形式出现；先写清要讲的内容，再决定视觉结构。
图、表、正文只有各自增加信息时才同时保留，不能机械执行“每节一图一表”。

通用段落长度、层级、留白、强调与图文对齐均遵循 [基础排版](layout-basics.md)，不只在知识讲解时启用。以下是教学组织的补充。

## 具体规则
- 分栏用于同屏对应或比较，不用于平分无关段落。需要比较时保持相同问题顺序。
- 图示贴近首次解释它的段落；每图明确回答一个问题，标出方向与必要条件。
- 版式层次优先靠语义标题和留白，颜色与加粗只强调少数关键信息；不用固定配色当通用偏好。
- 代码、公式和案例让读者能走通一次过程，不凭例子宣称性能提升或通用保证。
- 提示块与引用块区分：自己写的结论不伪装成外部引文。
- 列表编号连续，标题层级一致；交付前清除无意留下的占位词，待核实项则明确保留。
- 窄屏上比较分栏依阅读顺序转为单栏；表格保留表头和对应关系，可横向滚动。不能为适配窄屏删掉代价和条件。
- 纯文本环境用标题与比较表表达同样的信息，说明视觉限制，不假装已有图。

## 证据范围
读取文档样式可以确认分栏、列宽、强调方式和图文位置；不能单凭 XML、图片替代文本或画板占位推断画板美术质量。
只有实际查看渲染后，才评价拥挤、溢出、文字可读性和页面观感。
借鉴表达形式不等于接受范例的事实结论。参考原文、图片和内部链接不随本包携带。
